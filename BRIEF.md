# BRIEF — mercurius-claude-code

Claude по подписке владельца: сервис запускает неизменённый официальный Claude Code как одноразовый клиент одного
вызова модели и отвечает приложению по Messages API Anthropic. Модуль необязателен: без него у агента нет провайдера
`claude:`, остальное работает как раньше.

Требования и решения владельца — в спецификации основного репозитория:
[Claude по подписке](../../brief/models.md#claude-по-подписке). Образец — плагин Hermes
`claude-subscription-directsdk` ([конспект](../../docs/notes/hermes-claude-subscription-directsdk.md)).

Состояние на 2026-11-23: готовы каркас (здоровье, вход, окружение CLI) и один вызов модели — на подставном CLI и
подставном API. Сеть, лимиты и кеш — впереди; проверка против настоящего CLI — на сервере.

## Назначение и границы

Модуль делает:

- отвечает, работает ли CLI и каким входом пошёл бы запрос (`/health`, `/auth/status`);
- ведёт вход владельца в подписку: запускает `claude auth login`, отдаёт ссылку, передаёт код;
- собирает окружение дочернего процесса так, чтобы подписка не стала оплатой по ключу;
- на `POST /v1/messages` запускает CLI на один вызов модели за шлюзом допуска и отдаёт настоящий ответ API;
- отвечает списком моделей, которые знает по имени (`GET /v1/models`).

Остаётся в приложении Меркурия:

- цикл агента, инструменты, подтверждения, сжатие, память;
- выбор модели и переход на другую модель категории при исчерпанном лимите;
- команда владельца `/claude`, хранение токена `claude setup-token` в хранилище секретов;
- учёт вызовов и оценка стоимости.

Чего модуль не делает никогда: не шлёт запросы с токеном подписки сам, не читает и не правит файлы входа CLI, не
меняет CLI.

## Один вызов модели

1. Запрос разбирается до запуска CLI. Принимаются `model`, `system`, `messages`, `tools`, `max_tokens`,
   `stop_sequences`, `output_config.effort`, `thinking` (`adaptive`, `disabled`), `stream`; любое другое поле — `400`.
   Метки `cache_control` отбрасываются: их ставит CLI. JSON-объекты остаются объектами: пустой `input` не
   превращается в список.
2. На вызов создаётся каталог (права 700) с системным текстом, настройками CLI (тело-добавка в
   `CLAUDE_CODE_EXTRA_BODY`) и списком инструментов. Без инструментов MCP-сервер не поднимается.
3. CLI запускается на один ход: без своих инструментов, без настроек пользователя, без сохранения сессии, с одним
   идентификатором сессии на беседу. Адрес API для него — маршрут шлюза с секретом этого вызова.
4. История подаётся кадрами stream-json. Каждая реплика пользователя, кроме последней, идёт с `shouldQuery: false` и
   ждёт подтверждения с нулём ходов; последняя — запрос к модели.
5. Шлюз пропускает наружу первый `POST /v1/messages` вызова. Повтор, второй запрос и запрос другого вида получают
   локальный отказ. Исключение одно: после `401` с `authentication_error` — ещё один запрос, чтобы CLI обновил вход.
6. Ответ приложению — события самого API, как они пришли шлюзу, с именами инструментов приложения; без `stream` —
   собранное сообщение. Вывод CLI нужен только для подтверждений истории и для ошибок, которые CLI отвечает сам.
7. Ответ не ждёт выхода CLI: тот получает 10 секунд и снимается. Каталог запроса удаляется.

Ошибки: ответ API не 200 — его статус, тело и заголовки лимитов как есть; собственная ошибка CLI — статус по таблице
(`rate_limit` 429, `billing_error` 402, `authentication_failed` 401, `overloaded` 529, `server_error` 503); оборванный
ответ и выход без запроса — 502; доплата не разрешена — 429 от сервиса; тишина дольше `CLAUDE_CODE_IDLE_SECONDS` — 504; CLI не запустился — 503; не
дождался места в очереди — 529.

## Кеш промпта

CLI кладёт свой контекст запроса туда, где следующего запроса его уже нет: дату — в хвостовую системную реплику,
напоминание — перед репликой пользователя, заметку — в последний результат инструмента, а метку кеша — на этот
меняющийся хвост. Каждый запрос тогда пишет всю историю заново и ничего не читает. Шлюз (`src/PromptCache.php`) до
отправки: возвращает дату в сообщение окружения; убирает напоминания перед новой репликой и перед первым кадром
беседы; восстанавливает результаты инструментов к тому, что прислало приложение (только при совпадении
идентификаторов вызовов по порядку); переносит метку на последний блок, который повторит следующий запрос; после
длинной петли инструментов ставит ещё одну метку на начало хода. Запрос неожиданной формы уходит как есть. Разовый
вызов (без инструментов, одна реплика) идёт без меток сообщений и с кешем на 5 минут.

Замер 2026-11-24 на настоящем CLI 2.1.330: после первого вызова беседы доля чтения из кеша 94–99%.

## Сеть

Требование — [Сеть модуля Claude](../../brief/models.md#сеть-модуля-claude): один маршрут на оба плеча.

- Маршрут выбирается при старте: `VLESS_URI`, иначе `CLAUDE_CODE_PROXY`, иначе напрямую. Строит его `RouteFactory`
  пакета `mercurius-connectors`. Неразбираемый адрес — отказ старта; сам адрес в сообщение не попадает.
- **Плечо шлюза.** HTTP-клиент шлюза получает коннектор маршрута. TLS заканчивается на `api.anthropic.com`: прокси
  по пути входа не видит.
- **Плечо CLI.** Обновление входа, состояние плана и стартовые запросы CLI шлёт не в шлюз, а на хосты Anthropic сам.
  При заданном маршруте сервис поднимает свой прокси на loopback и отдаёт его ребёнку как `HTTPS_PROXY` /
  `HTTP_PROXY`; `NO_PROXY` — только loopback (шлюз). Прокси принимает только `CONNECT` на порт 443 хостов
  `anthropic.com`, `claude.ai`, `claude.com` и их поддоменов и открывает туннель через тот же маршрут. Отказ пишется в
  журнал с именем хоста — по нему список уточняется на настоящем CLI.
- При прямом маршруте прокси не поднимается, и ребёнку переменные прокси не задаются; прокси из окружения хоста
  ребёнку не передаётся никогда.
- `/health` называет маршрут полем `route`.
- Проверено вживую 2026-11-24 на экземпляре D: через VLESS и через HTTP-прокси с логином идут и запрос шлюза к API, и
  собственные обращения CLI (тестовый прокси на loopback записал подключения CLI к `api.anthropic.com:443`). С
  неверным паролем прокси вызов модели — 502, прямого выхода нет.
- **`get_usage` отвечает из кеша CLI, когда сети нет:** контейнер совсем без сети вернул прежние проценты окон.
  Поэтому `GET /usage` и состояние лимитов могут быть устаревшими, пока маршрут лежит; вызов модели в это время всё
  равно не проходит, так что доплата без ведома владельца из-за этого не начнётся.

## Лимиты и доплата

Требование — [Лимиты подписки и переход на модель категории](../../brief/models.md#лимиты-подписки-и-переход-на-модель-категории).

- **Откуда состояние.** Из события `rate_limit_event` в выводе CLI во время вызова и из ответа CLI на управляющий
  запрос `get_usage` (без вызова модели). Доплата идёт, когда событие говорит `isUsingOverage` или окно `overage`;
  по ответу `get_usage` — когда дополнительное использование включено и заполнено окно всего аккаунта (сессия или
  неделя). Ответ без времени сброса действует 15 минут, с ним — до сброса.
- **Слово владельца** приходит с вызовом заголовком `X-Claude-Extra-Usage`: `stop` (по умолчанию и при любом
  неизвестном значении), `allow`, `notify`. При `stop` сервис отказывает до запуска CLI — 429 с временем сброса;
  если состояние узнать не удалось — тоже отказ. `X-Claude-Extra-Usage-Reserve` задаёт порог в процентах: отказ
  раньше первого платного запроса.
- **Форма отказа** та же, что у API при исчерпанном окне: `anthropic-ratelimit-unified-status: rejected`,
  `anthropic-ratelimit-unified-reset`, `retry-after`, а в теле — `error.resets_at`. Так же оформляется отказ, который
  CLI даёт сам по исчерпанному окну. Приложение читает все три случая одинаково.
- Проверка идёт после ожидания места в очереди: вызовы, прошедшие за это время, могли пересечь лимит.
- `GET /usage` всегда спрашивает CLI заново и обновляет состояние.
- Режим `notify` для сервиса равен `allow`: сообщение владельцу раз на окно — дело приложения, состояние оно берёт
  из `GET /usage`.

## Безопасность и пределы

- Без `CLAUDE_CODE_TOKEN` (16+ символов) сервис не запускается; сравнение токена — за постоянное время.
- Порт наружу не публикуется: сервис только в сети `internal` Меркурия.
- Ключи `ANTHROPIC_API_KEY` и `ANTHROPIC_AUTH_TOKEN` до CLI не доходят: окружение ребёнка — белый список. Заданный
  `ANTHROPIC_BASE_URL` или переключатель Bedrock, Vertex, Foundry — отказ запуска, а не молчаливая подмена.
- Токен `claude setup-token` приходит от приложения заголовком запроса, живёт один запрос, в кеше состояния — только
  его хеш.
- Код входа, ссылка и вывод CLI в журнал не пишутся; stderr входа не сохраняется.
- Вход по ключу API или через облако CLI считает входом; сервис — нет (`metered`).
- Образ: пользователь `claude` без оболочки; каталог входа `/data/claude` с правами 700 — том.
- Имя модели уходит аргументом CLI, поэтому проверяется по образцу и не может начаться с дефиса; усилие — из
  закрытого списка; остальное из запроса попадает в CLI только файлами и вводом.
- Шлюз слушает только loopback; маршрут вызова — 24 случайных байта, знает его только CLI этого вызова. Адрес API
  задаётся кодом, из окружения не берётся; перенаправления и повторы клиента шлюза выключены.
- Заголовки запроса CLI (в том числе вход) идут к API через память и в журнал не пишутся; в ошибку шлюза попадает
  только класс сбоя, без текста.
- Тело запроса — не больше 32 МБ (столько принимает и сам API).
- Приложение отключилось — CLI вызова снимается, в том числе посреди ответа: запрос не оплачивается впустую.
- В настройках вызова чтение файлов запрещено (`permissions.deny: Read`): текст пользователя не должен заставить CLI
  приложить файл сервиса. Разворачивает ли CLI упоминания `@путь` в этом режиме — проверяется на настоящем CLI.
- Каталоги запросов, оставшиеся после аварийной остановки, удаляются при запуске.
- Контейнеру нужен `init`: снятый CLI оставляет дочерний MCP-процесс, и без `init` его некому собрать.
- Одновременно работает не больше `CLAUDE_CODE_MAX_CONCURRENT` процессов CLI (по умолчанию 4, около 250 МБ каждый).
  Остальные вызовы ждут места по порядку прихода; место занято до выхода процесса. Вызов, который не дождался за
  время `CLAUDE_CODE_IDLE_SECONDS`, получает 529 и не стартует с опозданием; отмена снимает его из очереди.

## Решения

- **CLI — один самодостаточный бинарник** (проверено на 2.1.330): в итоговом образе нет Node, бинарник копируется из
  стадии сборки. Версия закреплена аргументом `CLAUDE_CODE_VERSION`; автообновление выключено.
- **Вход без терминала** (проверено на 2.1.330): `claude auth login --claudeai` печатает ссылку в stdout и читает
  код из stdin, псевдотерминал не нужен. Приём кода настоящим CLI проверяется при первом входе владельца.
- **`/health` отвечает 200 без входа:** сервис нужен, чтобы войти. Здоров — значит CLI найден и не старше
  минимальной версии; каким входом пойдёт запрос, сказано в поле `auth`, и провайдера приложение предлагает по нему.
- **Состояние CLI кешируется на 30 секунд:** каждая проба — запуск процесса; вход и выход кеш сбрасывают.
- **Окружение ребёнка — белый список, а не копия с вычеркнутыми ключами** (отступление от образца): новый секрет в
  окружении сервиса не утечёт в CLI по умолчанию.
- **Приложению отдаётся ответ API, а не пересказ CLI** (отступление от образца): образец собирает ответ из событий
  CLI в формат chat completions; здесь вход и выход — Messages API, поэтому события идут как пришли шлюзу, и ждать
  итога CLI перед ответом не нужно.
- **Один шлюз на сервис, маршрут на вызов** (отступление от образца, где сервер поднимается на каждый вызов):
  в асинхронном процессе это один слушатель и таблица разрешений.
- **Инертный MCP-сервер — файл образа на PHP,** а не копия в каталоге запроса: в образе нет Python, а каталог
  запроса остаётся только данными.
- **Аргументы вызова инструмента, которые не разбираются как JSON, делают ответ незавершённым** (отступление от
  образца, который выбрасывает такой вызов): в потоке приложение видит события само, а собранное сообщение с
  потерянным вызовом выглядело бы целым.
- **Тело запроса CLI шлюз не меняет.** Перестановка меток кеша и стабилизация контекста — отдельная работа с
  замером; сжатие тела не берём.
- **Свой прокси перед маршрутом, а не адрес прокси ребёнку** (отступление от образца, который отдаёт CLI адрес
  прокси организации): CLI не умеет VLESS, а белый список хостов не даёт ребёнку выйти куда-либо ещё.
- **`[1m]` — только закреплённым моделям.** За локальным адресом CLI даёт длинное окно лишь по явному имени;
  неизвестная модель уходит как названа.
- **Режим `ask` образца не берём:** его роль играет переход приложения на другую модель категории.
- **Сжатие тела запроса к API не берём:** выигрыш образец получил замером на своей нагрузке; вернуться после
  замера на нашей.
- **`/v1/models` отдаёт закреплённую таблицу.** Список, который даёт сам аккаунт, добавляется при проверке на
  настоящем CLI.

## Проверки

`composer check` — PHPUnit, PHPStan (max), Psalm (уровень 1); CI — один job на PHP 8.2. Тесты идут на подставном
CLI, без входа и без платных вызовов. Проверка против настоящего CLI на подставном API — на сервере, не в CI.

Проверка против настоящего Claude Code 2.1.330 на подставном API (2026-11-23, экземпляр D, вход — фиктивный токен,
до подставного API не доходящий наружу):

- вызов с историей из трёх реплик и инструментом дал **один** запрос `POST /v1/messages?beta=true`; ответ подставного
  API пришёл приложению за 1,7 с;
- инструмент ушёл как `mcp__mercurius__weather`, реплики истории воспроизведены без запроса к модели;
- `@/tmp/canary.txt` в последней реплике **не** развернулся: содержимого файла в теле запроса нет;
- CLI сам добавляет в `messages` реплики с ролью `system` (дата, контекст сессии) и поля `thinking`,
  `context_management`, `output_config`, `metadata`; модель уходит без `[1m]` (длинное окно — заголовком). Это
  учитывается в работе с кешем;
- в каталоге входа после вызова появились `.cache/claude-cli-nodejs/<рабочий каталог>`, `plugins/`, пустой
  `sessions/` — истории беседы там нет (смотрели только имена и размеры).

## Обновление Claude Code

Формат stream-json, кадры `shouldQuery`, заголовки и тело запроса CLI — внутренние интерфейсы Claude Code и меняются
от версии к версии. Поэтому версия закреплена (`CLAUDE_CODE_VERSION`), автообновление выключено, и новая версия идёт
так:

1. Сменить `CLAUDE_CODE_VERSION` (в `Dockerfile` сервиса, в `docker-compose.yml` и `.env.example` основного
   репозитория), собрать образ на сервере
   разработки.
2. Проверка против настоящего CLI на подставном API (раздел «Проверки» выше): один запрос на вызов, история
   воспроизводится без запроса к модели, `@путь` не разворачивается, истории в каталоге входа нет.
3. Снимок формы запроса трёх подряд вызовов одной беседы: где метки кеша, что CLI добавляет к реплике и к результату
   инструмента. Изменилась форма — поправить `PromptCache` и его тесты.
4. Замер кеша вживую: после первого вызова доля чтения выше 90%.
5. Выкладка обычным обновлением.

Новая модель Claude — строка закреплённой таблицы `src/Models.php` (окно, псевдоним, обязательное рассуждение) в тот
же день, иначе длинное окно ей не достанется.

## Связь с Меркурием

  или `CLAUDE_CODE_PROXY`.
